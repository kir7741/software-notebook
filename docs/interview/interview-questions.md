# 面試考古題

### （ㄧ）、自我介紹

面試官好，我是 Joseph，目前是一名前端工程師，在軟體業大概有 8 年多的經驗，主要使用 Angular、React、Vue 等框架來開發產品與專案，而過去較常接觸的產業主要包含金融保險、教育，還有電商等。

我最早是在極限科技擔任前端工程師，公司的客戶主要是金融相關的產業，所以工作內容主要是用 Angular 來維護金融、保險客戶的內部系統跟後台管理平台。

後來我加入 25sprout，擔任資深前端工程師，除了一樣有使用 Angular 來開發保險產業的專案，也有負責用 React 跟 Vue 來開發電商平台以及其他客製化專案，過程中也常常跟 PM、設計師一起釐清需求、評估技術方案。後來因公司組織擴大與調整，我開始擔任前端副理，開始帶 5 到 6 人的前端團隊，開始負責專案的系統架構規劃跟任務拆解，還有協助新人上手專案並協助掌控團隊成員進度讓專案可以準時交付。

最近這兩年，我在 ViewSonic 擔任前端工程師，同時使用 Angular 跟 React 來負責開發與維護 VS Account、myViewBoard 等公司核心產品，服務對象主要是企業跟教育用戶。在 ViewSonic 這段期間，我跟設計師一起建立了內部的 Design System，製作 20 幾個可重複使用的元件，統一了產品間的設計標準，並提高了產品開發的效率。也更多的接觸了前端以外的領域，像是開始了解 CI/CD 流程，並能夠使用 AWS CloudFront 與 S3 部署前端專案，也有使用 NestJS 開發後端 API 的經驗，並且也有使用像是 Claude Code, OpenSpec 等 AI 工作流來輔助開發。

以上是我的簡短自我介紹，希望可以帶著這些經驗加入貴團隊，謝謝

### （二）、專案上遇到的問題 & 解決辦法

(ㄧ)、GTM 埋碼：這類問題本質上不是技術難題，而是資訊落差跟溝通責任的問題。當時我對行銷部門真正想追蹤的商業行為並不熟悉，如果被動等對方把規格文件寫好才動工，時程一定會被拖延，而且很可能規格本身就有缺漏。所以我選擇主動去找行銷跟數據團隊的窗口，直接了解他們想回答的商業問題，再回頭反推需要埋哪些事件、帶哪些參數，把模糊需求轉換成明確可驗收的規格。這也讓我建立起一個原則：跨團隊的依賴不能只是被動接需求，要主動往上游找資訊，才能把風險提前消化掉。

(二)、Infra 相關知識：接手 AWS CloudFront、S3 部署的工作時，我很清楚知道自己在雲端架構這塊是有知識落差的，與其邊做邊踩坑、用錯誤試出正確架構，我選擇先系統性地去上課、考取相關證照，把 CDN 快取策略、S3 靜態網站託管的機制搞清楚，再回頭設計部署流程。這讓我後續能獨立完成 5 個以上前端專案的部署，並把部署時間減少 40%。我認為 Senior 工程師遇到知識缺口時，比起邊做邊查零散資訊，更值得投資時間把底層原理搞懂，這樣做出來的方案才是可複製、可維護的，而不是碰巧堪用。

(三)、Flutter 打開專案：這其實是一個技術選型決策流程裡的方法論問題。在評估跨平台框架時，網路上的比較文章很多，但這些結論往往跟團隊的實際技術背景、專案需求不完全吻合。我沒有直接採信二手資訊，而是實際把 Flutter 專案打開來動手驗證，包含開發體驗、效能表現、跟現有技術棧的整合成本、團隊的學習曲線，用第一手數據支撐最後的技術決策。對我來說，技術選型的責任在於決策者要親自驗證關鍵假設，而不是把風險留給日後才發現。

### （三）、過去的管理經驗
ex: 如何協助新人上手

(一)、Onboarding 機制：帶 5 到 6 人團隊時，我意識到單靠一對一口頭傳承是不可規模化的，所以我把它系統化：建立 Mentor 制度讓每位新人都有固定對口，同時把前端開發規範、架構慣例、常見陷阱整理成文件，讓知識從「在我腦中」變成「團隊共同資產」。這讓 onboarding 時間穩定控制在三週內，也代表新人的產出品質不會因為帶他的人不同而有落差。

(二)、掌握專案進度與風險：站會對我來說不只是同步進度，更是風險雷達——透過每天觀察成員回報的內容跟語氣，及早抓出卡關、範疇不明或低估工時的訊號，在問題變成延遲之前就介入，調整任務順序或資源分配。這是團隊能維持 95% 以上準時交付率的關鍵，而不是靠事後加班補救。

(三)、Code Review 作為知識傳遞機制：我把 code review 定位成雙重目的的工具，一是品質把關跟架構一致性，二是新人成長的加速器。比起只給修改意見，我更著重在 review 留言裡解釋「為什麼」，讓新人理解背後的設計原則，而不是照抄修改，這樣他們才能逐漸內化團隊的工程判斷標準，而不是永遠依賴他人 review 才能寫出合格的程式碼。

### （四）、跨部門合作經驗／分派人力資源的經驗

(一)、與 PM 合作：我在跟 PM 討論需求時，會主動把商業目標拆解成技術可行性評估，例如金流與購物模組的串接、複雜表單的規劃、GTM 埋碼流程，並清楚指出哪些地方有技術限制、哪些地方有多種實作路徑跟對應的成本／效益，讓 PM 能在還沒開發前就做出更精準的優先順序判斷，而不是等到開發中才發現規格不可行。

(二)、與設計師合作：除了日常討論登入模組、表單操作流程等 UI/UX 細節，比較能代表 Senior 高度的合作經驗，是跟設計師一起從零建立內部 Design System。這不只是元件開發，更包含跟設計師一起定義設計 token、元件的可組合性跟擴充規則，確保系統本身能長期演進而不是一次性專案，最終產出 20 幾個可複用元件，並讓功能交付速度提升 20% 以上。

(三)、與後端工程師合作：我會參與 API 契約跟資料結構的設計討論，並在技術選型上提供意見，例如非同步結果要用 websocket、SSE 還是 polling，這類選擇要考量的是即時性需求、伺服器負載、跟前端的複雜度取捨；以及 RESTful API 跟 GraphQL 之間的權衡，要看資料形狀的彈性需求跟團隊的維護能力。這些討論的核心是幫團隊在還沒寫程式碼前，就先把架構層級的風險排除掉。

(四)、分派人力資源：我的原則是先用重要緊急程度做任務分類，再評估每個成員當下的 loading 跟成長階段，最後才依照專長分派任務——但我也會刻意把部分任務分給還沒有該項經驗、但有能力挑戰的成員，並搭配適當的 support，讓分派任務同時達成專案進度跟團隊能力成長兩個目標，而不是永遠讓最熟練的人做同一類事。

### （五）、做過最自豪的技術決策或產品功能

(一)、跨平台框架的選擇（Flutter vs React Native vs Ionic）：這個決策最有價值的地方不是「選對了哪個框架」，而是我建立了一套用實測數據驅動技術選型的流程，避免團隊被單一觀點或流行趨勢影響，把開發體驗、效能、生態系成熟度、團隊學習曲線都量化成可比較的評估依據，這套方法論後來也成為團隊做重大技術決策時的參考模式。

(二)、Design System 的建立：這是我認為最能代表架構層級思考的產出。我跟設計師合作建立的不只是 20 幾個 UI 元件，而是一套跨產品線（VS Account、myViewBoard 等）共用的設計與開發標準，解決了多產品各自為政、重複造輪子的問題。它帶來的效益是可衡量的——功能交付速度提升 20% 以上——但更長期的價值在於，它降低了新產品跟新成員加入時的學習成本，是一個會隨著產品線增加而持續複利的投資。

### （六）、根據你最有印象的專案，描述使用的技術，功能的拆分，實作到部署，一整個流程參與了什麼

以 ViewSonic 的 myViewBoard 為例，這是服務教育與企業用戶的核心產品之一，我在這個專案裡的角色橫跨了實作、架構決策跟流程管理。

- 技術架構：前端主要用 Angular 與 React 開發，樣式方案依需求選用 SASS/SCSS、CSS Module、Tailwind，並搭配內部 Design System 元件庫，確保新功能能直接複用既有的設計跟程式碼資產，而不是每次從零開始；部分後端 API 用 NestJS 開發，讓我在做前端架構決策時，能同時考量到跟後端的資料契約設計；建置工具用 Webpack/Vite，並透過 Github Actions／Gitlab CI 建立 CI/CD pipeline，最終部署到 AWS CloudFront 與 S3。
- 功能拆分的決策：拿到需求後，我不會直接切任務給團隊，而是先跟 PM、設計師釐清商業目標跟操作流程，評估技術風險最高、不確定性最大的部分，優先拆出來驗證；同時盤點是否有現成 Design System 元件可複用，把團隊的開發資源集中在真正需要客製化的邏輯上，而不是重工既有的 UI。
- 品質與效能治理：我主導把無障礙設計納入這個專案的開發標準，讓網站符合 WCAG AA，並針對 CLS 做效能優化，把分數壓到 0.1 以下——這類非功能性需求容易被忽略，但長期影響使用體驗跟 SEO，我認為 Senior 工程師的責任之一就是把這些「看不見的品質」制度化進開發流程，而不是等出問題才補救。
- 協作與流程：開發過程透過 code review 確保架構一致性，站會同步進度與風險；我同時擔任 Scrum Master，管理團隊的 sprint 節奏，這讓我能同時從工程跟流程兩個角度去平衡交付速度與品質。
- 部署與維運：功能完成後透過 CI/CD pipeline 自動化測試與建置，部署到 CloudFront 與 S3，整個流程的自動化跟架構優化讓部署時間減少 40%，也代表團隊能用更高的頻率、更低的風險把功能推上線。

整體來說，從需求釐清、架構規劃、元件與 API 設計，到品質治理、流程管理跟最終部署，我在這個專案裡負責的不只是「寫程式碼」，而是確保整個團隊在正確的架構跟節奏下持續交付，這也是我認為 Senior 前端工程師最核心的價值所在。
